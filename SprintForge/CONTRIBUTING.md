# Contribuindo com o SprintForge

Obrigado pelo interesse em contribuir com o SprintForge!

O projeto reúne práticas de desenvolvimento ágil, incluindo Scrum, Kanban e Extreme Programming (XP).

## Fluxo de contribuição

1. Crie uma branch a partir da versão atualizada da `main`.
2. Realize uma alteração pequena e com objetivo bem definido.
3. Revise as modificações antes de criar o commit.
4. Execute as validações aplicáveis ao projeto.
5. Abra um Pull Request descrevendo a alteração realizada.

## Convenções de commits

Utilize mensagens claras e objetivas, preferencialmente seguindo estas categorias:

- `feat:` novas funcionalidades.
- `fix:` correções de problemas.
- `docs:` alterações na documentação.
- `refactor:` melhorias internas sem alteração intencional de comportamento.
- `test:` criação ou atualização de testes.

## Boas práticas

- Evite misturar alterações sem relação no mesmo Pull Request.
- Preserve as funcionalidades existentes.
- Não inclua credenciais ou informações sensíveis.
- Documente mudanças relevantes.
- Mantenha a comunicação respeitosa e construtiva.

## Revisão

Antes de enviar sua contribuição, verifique se as alterações estão restritas ao objetivo proposto e se não existem arquivos adicionados acidentalmente.

## Coautoria em commits

Quando duas ou mais pessoas colaborarem em uma alteração, a contribuição pode ser reconhecida utilizando o trailer `Co-authored-by` na mensagem do commit.

Exemplo:

```text
Co-authored-by: Nome do Colaborador <email-vinculado-ao-github>
```

O e-mail informado deve estar associado à conta GitHub do colaborador.

O trailer deve representar uma contribuição efetiva, e não apenas uma atribuição simbólica.

Antes de publicar o commit, revise as alterações e confirme que todos os colaboradores foram identificados corretamente.

## Critérios para Pull Requests

Para manter a qualidade e a organização do SprintForge, as contribuições devem seguir alguns critérios:

- **Escopo definido:** cada Pull Request deve tratar de uma melhoria ou correção específica.
- **Compatibilidade:** as alterações não devem comprometer funcionalidades existentes.
- **Validação:** execute os testes e verificações disponíveis antes de enviar a contribuição.
- **Documentação:** atualize as instruções quando houver mudanças relevantes no funcionamento do projeto.
- **Descrição clara:** explique o objetivo da alteração e como ela foi validada.

Pull Requests devem ser avaliados quanto à integridade das alterações, à ausência de conflitos e aos resultados das verificações automatizadas, quando disponíveis.
